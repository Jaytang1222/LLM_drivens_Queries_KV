# 第五轮对比实验优化：决策语义、收益误差与 KEEP 调度

日期：2026-10-01。

## 1. 目标与交付状态

本文件承接 [第四轮方案](comparative_refine_4.md) 和 [第四轮交付物](refine_4/summary.md)。目标仍是在 CBO-first、当前查询真实调用 LLM、完整安全验证的前提下，使 hybrid 相对同配置原生 CBO 获得真实端到端净收益。

**本文是待实施指导，不是第五轮结果。** 本次只新增文档，没有修改代码或运行实验。引用数字来自既有第四轮文件；源码观察来自本地实现，开发前需核对服务器构建。

本轮重点从继续压缩输出转为：解释并纠正 9/9 KEEP 的原因，校验收益门控依据，修正隔离计时，再减少 KEEP 的串行等待。

不立即扩大全量实验，不新增数据集，不强迫模型选择特定计划。先做低成本协议诊断，再用已有开发查询验证。

## 2. 第四轮证据与边界

### 2.1 已测结果

根据 [summary](refine_4/summary.md) 和 [短决策报告](refine_4/llm_short_decision.md)：

- 同跑 CBO 对比为 0 胜、9 负，Oracle 全通过。
- hybrid 九条全部 KEEP，负收益误采纳为零，正收益机会采纳也为零。
- LLM 延迟中位数 1,217 ms，最小 688 ms，最大 2,955 ms。
- 输入 token 中位数 126，输出中位数 6，输出上限 16。

短协议已显著减少调用成本，但“全部不采纳”不能作为选择器有效的证据。

### 2.2 两条机会并非被数值门槛直接拒绝

[逐行决策](refine_4/llm_short_decision.jsonl)中：

- Fréchet：prefer 预测节省约 1,355 ms，投机已启动，LLM 返回 KEEP。
- DTW：prefer 预测节省约 1,915 ms，投机已启动，LLM 返回 KEEP。

它们不是被 500 ms 投机门槛拦截，也不是合法提议被 200 ms 采纳门槛拒绝。当前直接原因是模型输出 KEEP；为什么这样输出仍待诊断。

### 2.3 协议语义不完整是可检查的问题

本地短提示提供 `s_hat` 和输出格式，但未充分解释单位、正负方向、执行收益与净收益的区别，也缺少明确优化目标。

这支持优先修正任务说明，但尚不能证明它是全部 KEEP 的唯一原因。模型能力、缺少必要信息、风险偏好和位置偏好也需要区分。

### 2.4 机会仍值得验证

[执行隔离](refine_4/execution_isolation.md)的独立执行中位数：

- DTW：P_T 1,362 ms，P_TZ 2,692 ms。
- Fréchet：P_T 734 ms，P_TZ 2,686 ms。

这是固定计划的开发证据，不是正式 E2E 净收益，也不能直接与另一跑次的 LLM 时间拼接成获胜结果。

## 3. 固定实验边界

- 原生 CBO 的搜索与选择规则保持不变。
- 公共验证器、执行器优化两臂一致使用，基线同跑重测。
- 不绕过安全检查，不因计划 ID 已见过就跨语义复用验证。
- 不硬编码查询→赢家，不要求 AIS 必须选 P_T。
- 不以降低门槛直到获胜作为调参方法。
- 不新增强非 LLM 正式对照臂；内部协议测试和归因诊断单独标记。
- 保留负结果、回退、超时、投机浪费和未结束后台任务。
- 本轮主口径仍逐条调用 LLM，且返回等待该决策或规定的超时处理；先返回 CBO、后台再调用属于另一协议。
- 九条已有查询是开发集；未知验证需后续冻结后另做。

## 4. 阶段 A：低成本决策协议诊断

### 4.1 先修正输入语义

保留短输出，但把关键字段定义清楚：

- `exec_saving_ms`：CBO 预计执行时间减候选预计执行时间，正值表示候选更快。
- `candidate_exec_ms`、`cbo_exec_ms`：执行估计，均非实测答案。
- `saving_uncertainty_ms`：经校准的误差信息；尚未校准时明确 unknown，不能填零。
- `schedule_mode`：候选预先投机，或 LLM 决策后才执行。
- `estimated_extra_critical_path_ms`：相对 CBO 新增关键路径的估计，说明是否已含调用、准备与竞争。

不应机械地将所有字段都塞进提示。先固定一份语义完整的最小契约，再测输入成本。所有预测必须在线可得，不能提供当前测试实测赢家。

### 4.2 提示契约示意

以下为待验证的任务描述，不是已经确定的最优提示：

```text
选择预计端到端完成更快的安全方案。
exec_saving_ms 单位为毫秒，正值表示候选比 CBO 执行更快；它尚未扣除额外关键路径成本。
所有数值均为预测，误差未知不等于零。
根据给定调度、预测收益、额外成本和不确定性判断是否有足够净收益。
证据不足或预计净收益非正时 KEEP；否则选择合法候选编号。
只输出一个 choice JSON，不输出解释。
```

输出仍可采用 `{"choice":"KEEP"}` 或 `{"choice":N}`。不要用始终示范编号 0 的方式隐含“第一个是答案”；映射由每次请求确定，解析后校验范围。

如果数值已完全决定选择，应使用确定性规则校验算术，并把 LLM 定位为协议理解/信息判断的待验证组件。不能把简单照抄最大数值宣称为 LLM 增量价值。

### 4.3 不执行数据库的合成测试

设计以下类别，每类含若干固定种子变体：

1. 明确负收益。
2. 明确正收益且足以覆盖新增成本。
3. 执行正收益但 E2E 净收益为负。
4. 误差范围跨越零，保守策略应 KEEP。
5. 单位/符号一致的等价表示。
6. 候选顺序互换，方案语义不变。

示例数值仅用于合成诊断：执行节省 1,800 ms、额外关键路径 400 ms、经过定义的保守误差余量 200 ms，可构造明确正例；节省 100 ms、成本 800 ms 为明确反例。这些不是项目实测。

合成输入必须遵守同一计算定义。对于投机，先由测试生成器根据事件依赖得到正确关键路径，不能把全额调用时间重复扣除。

记录提示版本、原始输出、解析结果、选择类别、格式合法率、明显正例召回、明显反例误采纳、顺序一致性、实际 token 与耗时。

### 4.4 推进条件

- 修正后的协议能够同时处理清晰正例和反例，不再固定 KEEP 或固定第一项。
- 不同顺序下语义等价案例的选择基本一致，异常明确保留。
- 若仍不能理解，先检查解析和映射，再评估模型；不立即跑九条 E2E。
- 合成通过只证明契约理解，不证明数据库收益和泛化。

**期望收获：**低成本区分协议歧义、解析问题、位置偏好和模型能力，避免用昂贵实验反复发现“仍全部 KEEP”。

## 5. 阶段 B：校准收益差值和不确定性

### 5.1 现有证据不足之处

第四轮校准为 958 条开发记录拟合，绝对执行时间 MAE 约 1,043 ms，无分组 holdout。该误差不能直接等同于收益差值误差，也不能据此证明 200/500 ms 门槛必然错误。

下一步应直接评估：

```text
S_actual(q,p) = E_cbo(q) - E_p(q)
residual(q,p) = S_pred(q,p) - S_actual(q,p)
```

同时保留正负误差：高估收益可能误采纳，低估收益会丢失机会。

### 5.2 实施步骤

1. 核对训练特征与线上特征来源、单位和预处理是否一致。
2. 同一查询的候选和重复测量保持在同一分组，避免泄漏。
3. 按数据集、查询族分层报告，同时说明样本量；数据不足不单独拟合不可靠分层模型。
4. 分开独立与并行执行标签；并行惩罚不可凭单次测量固定。
5. 通过开发内部留出/交叉验证估计收益残差，门槛不使用最终未知测试结果调优。
6. 记录正收益召回、负收益误采纳、收益误差和 regret，不只报告零误采纳。

已有九条反复调过，不能改名为 holdout。对历史普查做分组验证可用于开发模型选择，但不自动成为最终未知泛化证据。

### 5.3 缺失特征处理

本地 `BenefitCalibrator` 将缺失特征返回零。先检查真实数据是否发生以及频率；不能预先把它认定为本轮 KEEP 的原因。

建议区分：

- measured/estimated zero：确实为零。
- missing：未知，带缺失指示或回退到明确的保守估计。
- invalid：单位/类型错误，记录并停止使用该预测。

缺失或异常不能悄悄获得“免费扫描/免费回表”的低成本解释。绝对时间预测若可能为负，不应用其作为合法时长；差值模型与时间模型要明确分开，不能随意截断后不重评排序。

### 5.4 门控要求

门槛根据残差和实际额外成本确定，不能简单把 500 改成 0。初期允许显式 unknown 和保守回退，但必须报告因不确定性丢失的机会。

门控负责确定性数值约束，LLM 不能绕过安全或硬预算；LLM 与门控各自的拒绝原因单独记录。

**期望收获：**建立可靠程度可解释的收益依据，既避免坏计划，也不以零采纳掩盖选择器失效。

## 6. 阶段 C：修正隔离计时及竞争结论

### 6.1 现有字段含义

本地 `FixedPlanIdArm` 在执行结束后围绕 Future.get 计时，该字段表示剩余等待，不是完整 LLM 调用时长。因此第四轮隔离行中 `llm_latency_ms=0` 不等于请求没有成本。

这项观察针对固定计划隔离工具，不能外推为主 hybrid 所有 LLM 计时均错误。开发前分别检查字段生产路径。

### 6.2 建议改法

在实际请求任务内记录：

- 提交、任务开始、请求开始、响应完成、解析完成时间。
- 执行开始/结束、主线程开始/结束等待时间。
- 请求状态、超时、取消、异常和后台真正结束时间。

分别命名完整调用、排队和执行后等待；使用单调时钟，不将等待与调用相加。响应 token/加载等无法获得时保留缺失原因。

异步指标必须在任务结束后可靠回收，不能因为主线程没等就把未写入字段记为零。

### 6.3 最小复核

使用与主实验相同的短提示，不再只用 dummy KEEP；固定同一查询、同一计划、同一资源，分别独立和并行运行，轮换顺序。

建议先每项 3 次开发配对，记录波动。第四轮并行每项一次，只能支持竞争迹象，不足以声称统计显著或得到稳定竞争惩罚。

**期望收获：**恢复可解释的调用/执行重叠时间线，并判断下一步调度能否真正隐藏等待。

## 7. 阶段 D：按机会决定执行什么，与 LLM 重叠

### 7.1 两条执行路径

初期最多一个数据库执行任务与 LLM 并行，不同时盲目跑 CBO 和多个候选：

- 有可信机会：准备并投机一个候选，同时调用 LLM。
- 无可信机会：执行 CBO，同时调用 LLM。

仍保留逐条调用与等待决策契约。不得将没有使用 LLM 决策的早返回行计为本协议的 LLM 获胜。

### 7.2 分支处理

- LLM 选择已运行计划：验证结果有效后复用执行结果，等待所有返回条件满足。
- LLM 选择另一候选：验证新计划，处理已有任务取消，再执行真实选择；记录浪费与延迟。
- LLM KEEP 而投机的是 novel：回到 CBO，计入已浪费工作，不能把投机结果当 KEEP 答案。
- LLM 超时/非法：遵守事前固定回退规则，不隐藏等待和残留推理成本。

无可信机会不等于绝对不允许模型发现新机会；若允许改选，需要明确它仍受哪些数值与安全约束，以及从头执行的代价。

### 7.3 时延解释

令 C 为 CBO-first 阶段，L 为调用，V/E 为 novel 准备/执行，E_c 为 CBO 执行，R 为其他关键路径成本：

```text
novel 被采用：T ≈ C + max(L, V + E) + R
CBO 并行且最终 KEEP：T ≈ C + max(L, E_c) + R
先等 LLM 再执行 CBO：T ≈ C + L + E_c + R
```

这是理想依赖关系示意，真实资源竞争、调度和取消仍以墙钟为准。KEEP 并行可能减少串行损失，不能保证超过 CBO；短查询仍受 LLM 下界限制。

LLM 决策时部分成本已支付：是否继续执行某计划属于剩余成本决策；是否最终净胜则必须计入全部已支付成本。不要把沉没成本从实验 E2E 中删除。

**期望收获：**减少“相同 CBO 答案但额外串行等待一次模型”的损失，明确投机和回退的真实代价。

## 8. 阶段 E：恢复机会的最小数据库验证

在协议理解和计时检查通过后，使用现有 AIS DTW、Fréchet，并保留普通对照。它们均为开发案例。

先固定模型、候选空间和新验证器，单独改变任务说明；随后才改变门控或调度。不要同时更换模型和校准器后宣称收益来自提示。

每条记录：

- 实际发送的输入、原始响应、解析结果、编号映射和提示版本。
- 各候选预测节省、不确定性、成本来源与门控判定。
- 投机计划、LLM 提议、最终计划以及选择来源。
- 执行、调用、准备、等待、取消和真实 E2E。
- Oracle、失败、回退及投机浪费。

日志不包含凭据；输入含数据时遵循项目既有数据处理方式。

不能把“模型开始选 P_T”当成功。必须检查合法性、同轮执行收益及扣除全部开销后的净收益。若 KEEP 仍然合理，应保留结果；若明确正收益合成案例也失败，则返回协议或模型诊断。

开发前核对源码和运行 jar，尤其是热补丁构建身份。以下测试针对真实剩余风险：

- 明显正/负净收益语义测试及顺序等价性。
- KEEP、合法编号、越界、截断、非法 JSON 与超时解析。
- 缺失特征不冒充零、错误单位不进入预测。
- 请求完整时长与执行后等待分开，无响应时不填零。
- 已运行计划与最终选择相同/不同的执行、取消和回退路径。
- 计划复用的语义/版本一致性与 Oracle 回归。
- 全部尝试保留在统计中，不通过删除失败提高成绩。

## 10. 推进顺序与验收门槛

1. 离线合成协议诊断，确认模型理解任务。
2. 收益残差评估与隔离计时修正。
3. 两条 AIS 机会加普通对照，检查采纳恢复及收益。
4. 根据事件时间线改 KEEP/投机调度。
5. 回到全部九条开发查询，统一新 CBO 基线配对。

建议每个阶段预先固定重复次数和顺序规则；观测不确定时报告不确定，不反复跑到正结果即停。

只有开发收益可重复且错误/退化受控，才冻结代码、模型、提示与门槛，开展未按 hybrid 胜负筛选的未知查询验证。不能把反复调参的九条升级为正式泛化证据。

### 停止或转向

- 明确信息下模型仍固定 KEEP/第一项：评估模型或任务适配，不强制候选输出。
- 校准误差与机会同量级且不可控：补充代表性开发数据或统计，不盲目降低阈值。
- 候选执行更快但调用/竞争仍盖住收益：继续降低相关开销或承认当前场景边界。
- 只有校准器贡献，LLM无额外判断价值：如实归因，不能把“发生调用”等同于“LLM有效”。
