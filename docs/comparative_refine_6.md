# 第六轮优化指导：执行反馈、预算内探测与 LLM 受限提议

日期：2026-10-01。

## 1. 本轮选择与状态

本文件承接 [第五轮方案](comparative_refine_5.md) 和 [第五轮交付物](refine_5/summary.md)。目标仍是在 CBO-first、当前查询真实调用 LLM、完整安全验证的条件下，验证 hybrid 是否能获得相对同配置原生 CBO 的端到端净收益。

**本文件是待开发方案，不是第六轮完成报告。** 编写时只新增本文，未修改代码、未运行实验。本轮不应立即扩大查询集或再次直接跑完整实验。

核心路线调整为：

> 修正决策证据链 → 校准执行前统计 → 不确定时进行预算内局部探测 → LLM 提议值得检查的机制/候选 → 确定性程序完成安全与收益判断。

不再把小模型同时当作成本计算器、风险判断器和最终执行调度器。近期先实现上述最小闭环；查询内分区混合访问作为中期研究扩展，暂不混入近期开发范围。

## 2. 为什么需要改变路线

### 2.1 规划变慢的直接组成

第五轮 [AIS 原始行](refine_5/ais_e2e.jsonl)显示：

- DTW：规划 3,869 ms，LLM 3,709 ms，校准 4 ms。
- Fréchet：规划 4,854 ms，LLM 4,664 ms，校准 3 ms。
- 两条输入均为 299 tokens，输出均为 6 tokens。

这些行约 96% 的规划时间为 LLM 调用。提示变长是值得验证的因素，但没有推理分段证据时，不能把全部增长都归因于输入长度。

### 2.2 格式通过不等于决策通过

[合成测试](refine_5/decision_synthetic_eval.md)：format_ok=8/8，明确正例召回=2/4，反例正确 KEEP=0/4，顺序一致性=0/3。

因此只能说输出格式问题得到改善，不能说模型已经理解并稳定执行净收益决策。继续追加调度和风险说明可能进一步增加延迟，未必改善判断。

### 2.3 汇总混淆了不同失败原因

原始行中，DTW 的 prefer 预测节省约 1,915 ms，而模型所选候选对应节省约 382 ms；Fréchet 为约 1,355 ms 对 498 ms。两条均有实际投机启动和浪费记录。

本地代码在门控拒绝后将 `llm_action` 改为 KEEP，部分摘要同时显示 `spec=False`。由此不能直接解释成“模型主动全部 KEEP”或“没有投机”。

这是证据表达需要修正的地方，不证明数据造假。应先保留原始选择，再区分模型选错、门控拒绝和主动回退。

### 2.4 当前误差不是线上决策误差的完整估计

[收益残差报告](refine_5/saving_residual_validation.md)明确使用实测 ranges/fetch/index 代入模型，而线上使用 FastCost 估计特征。报告中的收益 MAE≈1,331 ms 未完整计入线上特征估计误差。

MAE 是平均绝对误差，不是可直接解释为置信界的统一扣减值。不能因为它约为 1,331，就认定减 1,000 或 1,331 ms 能提供已证明的保护。

## 3. 与相关研究的关系

以下对应关系基于已核对的公开摘要，非完整论文复现或穷尽性新颖性检索。

### 3.1 LEO：先修正统计与基数估计

[LEO — DB2’s LEarning Optimizer](https://research.ibm.com/publications/leo-db2s-learning-optimizer)利用已执行查询的估计值与实际值差异，反馈修正统计和后续优化。

可借鉴：在 KART 中校准扫描量、联合过滤后的候选规模和回表量，再估计计划成本。不是只在最终耗时上增加一个全局回归系数。

### 3.2 Bao：利用现有优化器，学习如何引导

[Bao: Making Learned Query Optimization Practical](https://doi.org/10.1145/3448016.3452838)及其[公开摘要](https://arxiv.org/abs/2004.03814)说明了基于现有优化器、优化提示与执行反馈进行学习的方向。

可借鉴：保持 CBO 为可靠起点，学习有限的候选扩展/探测动作。本文不要求替换现有 Bao 比较臂，也不将新的 hybrid 称为 Bao 原生复现。

### 3.3 SkinnerDB：用当前查询的执行反馈更新判断

[SkinnerDB: Regret-bounded Query Evaluation via Reinforcement Learning](https://doi.org/10.1145/3464389)通过时间片执行、进度反馈和专用机制调整连接顺序。

可借鉴：当估计不可靠时，获取少量当前查询证据再决定。KART 的 KV 扫描与轨迹计算不同，不能直接声称获得 SkinnerDB 的 regret 界、切换能力或结果合并保证。

### 3.4 本项目的研究假设

有潜力研究的组合是：**面向轨迹 KV 查询，依据时空相关性与访问碎片化，选择是否以及在哪里获取额外统计；由 LLM 提议探测或安全改写，确定性执行器控制预算与覆盖。**

这些是待验证的设计方向，不是已确认的学术创新。候选选择、采样、反馈校准本身已有研究基础；只有证明具体机制有额外价值，才能形成可信贡献。

## 4. 固定边界与公平性

- 原生 CBO 的搜索与选择规则不弱化；公共验证器/执行器优化两臂一致生效并重测基线。
- 不绕过安全验证，不把性能置信度当成正确性证明。
- 不硬编码查询 ID→赢家，不固定 P_T/P_Z 偏好。
- 不根据 hybrid 胜负补选查询，不通过删负结果提高成绩。
- 主比较保持逐条 LLM-on；若跳过调用或先返回答案，另立协议。
- 在线探测、统计提取、模型请求、废弃投机和回退成本全部记账。
- 不新增强非 LLM 正式对照臂；内部归因诊断不混入正式方法主表。
- 九条已知查询继续作为开发集；未知验证在实现和参数冻结后进行。

## 5. 阶段 A：先修正决策证据链

### 实施指导

保留不可覆盖的原始字段，建议新增或分离：

- `llm_raw_response`、`llm_parse_status`。
- `llm_proposed_action`、`llm_proposed_plan_id`。
- `gate_decision`、`gate_reason`、`gate_evidence`。
- `final_plan_id`、`final_selection_source`。
- `speculation_requested`、`speculation_started`、`speculation_completed`、`speculation_used`、`speculation_waste`。
- prefer 及模型实际提议候选各自的预测值，不能只输出 prefer 数值解释另一个候选。

旧字段若保留，写清其历史含义。原始模型输出不被门控覆盖。摘要由明确 schema 生成，缺失与 false 分开处理。

### 验收

选取主动 KEEP、合法提议后被拒、提议被采用、解析失败四种用例，逐一核对原始日志、逐行 JSON 和摘要。

**期望收获：**回答究竟是模型没有发现机会、选了次优候选，还是门控依据不足，避免再次针对错误原因优化。

## 6. 阶段 B：执行反馈校准

### 6.1 建立统一特征契约

每个 query/plan 同时记录执行前估计与执行后实际值：

- 范围数量与 RPC。
- 索引扫描行数。
- 各访问分支候选量、交集输出量、去重后 chunk 数。
- chunk 回表量、完整轨迹读取量和字节量。
- 访问局部性、相似度工作量等当前可观测特征。

核对字段生产位置、单位和阶段。实际值只作为离线反馈标签，不能作为同次在线决策输入。缺失是 unknown，不是零。

训练数据如果只有实际特征，应补充对应快照下可重建的执行前估计；无法重建的样本保留为诊断，不能冒充线上特征训练集。

### 6.2 先校准机制，再估计耗时

优先回答：

1. 时空交集能减少多少候选？
2. 回表量与实际读取代价是否线性，何时受局部性影响？
3. 范围碎片化与 RPC 成本之间的关系是什么？

先从简单分层修正或小模型开始，不要求复杂神经网络。分层可以使用访问类型、时间跨度、区域统计和查询算子，但不使用 query ID 记忆答案。

输出包括候选执行估计、相对 CBO 的收益估计以及误差依据。独立执行与并行竞争数据分开，不能直接混成统一延迟标签。

### 6.3 单侧风险余量

定义收益高估残差：

```text
r = S_pred - S_actual
```

用开发内部留出记录估计 r 的上侧分位数，构造经验保守收益。样本不足或分布变化时标明不确定。选择分位水平应事先固定并报告验证覆盖率。

不得将经验分位数直接称为无条件概率保证；相关重复样本、区域变化和数据漂移会破坏简单独立同分布假设。同一查询的候选、重复测量和近重复语义应留在同一分组。

### 验收与收获

报告收益误差、单侧高估、正机会召回、负收益误采纳和不同查询族的表现。不是只要求误采纳为零。

**期望收获：**从“统一扣一秒”转向可解释的风险控制，同时查明哪些不确定性值得在线探测。

## 7. 阶段 C：有预算的局部探测

### 7.1 何时值得探测

只有以下条件同时满足时进入探测：

- 当前信息不足以明确区分少量候选。
- 存在足够大的潜在执行收益。
- 可通过低成本统计减少关键不确定性。
- 预计信息收益可能覆盖探测成本。

信息价值初期可用明确启发式和开发测量近似，不必立刻建立复杂决策过程；不能把未验证分数称为精确价值估计。

短查询或无明显机会直接保留 CBO 路径；在主协议下仍支付 LLM 调用，不能据此宣称已消除短查询下界。

### 7.2 最小探测动作

第一版只实现一个最有依据的动作：**对查询覆盖内的少量时间/空间分层，估计联合过滤后的候选规模与回表量。**

优先使用已有同快照统计或样本；不足时才读取受限索引片段。不得把完整执行两个计划称为“轻量探测”。

探测只提供选择证据，不直接用样本答案代替完整结果。采样索引如何代表总体需写明；无已知抽样概率时，不给出虚假精确置信区间。

### 7.3 分层、偏斜与预算

- 不只取前几个 RowKey，避免排序和轨迹热点偏差。
- 按事前规则在时间段/空间区域分层，使用固定种子。
- 记录命中热点、样本量和未覆盖分层。
- 同时限制墙钟、RPC、行数/字节和并发，超限停止。
- 预算与预计查询规模关联，不能对所有查询统一花一秒。

可先在开发中试若干小预算，如 25/50/100 ms，但这些是候选配置，不是已可实现目标。HBase RPC 的实际超时和取消可能超过逻辑预算，必须测量真实超限与后台完成情况。

### 7.4 探测后决策

更新联合选择率/回表估计，重新计算候选与 CBO 成本。若证据仍不足，停止探测并回退；不能在模型不喜欢结果时无限补样本。

若重用探测读取到的数据，需绑定同一快照和真实键范围，且记录收益包含数据复用；第一版可以先不复用，以减少实现复杂度，但探测暖缓存的效果仍需诚实计入方法成本和收益。

### 验收与收获

内部比较探测前后估计误差、选择变化、实际收益和探测成本。只有改善超过成本才继续。

**期望收获：**将“不确定就全部拒绝”变为“在值得时花小预算获取证据”，优先恢复真实机会。

## 8. 阶段 D：LLM 受限提议，不做最终数值裁判

### 8.1 任务定义

LLM 根据精简 BoundIR、统计不确定性和访问路径摘要，提议一个值得检查的机制或候选。例如：

- 检查时空相关性/交集规模。
- 检查范围碎片化。
- 提议时间访问候选。
- 提议联合访问候选。
- 无额外提议。

第一版只开放实际已实现的动作，不同时加入大量改写。模型输出受限 action ID；参数来自受限枚举或由确定性程序绑定，不能生成任意执行代码。

### 8.2 最小流程

```text
CBO SafePlan + 在线特征
→ 一次短 LLM 提议
→ 动作合法性与探测预算检查
→ 必要时局部探测/候选构造
→ 完整计划安全验证
→ 确定性收益判定
→ 执行或回退
```

此流程中的依赖步骤不能假装全部并行：LLM 提议后才知道做什么探测，则模型时间在探测前。只有与动作无关的特征准备可以提前重叠。

### 8.3 短提示与贡献判断

模型不需要阅读完整耗时表或执行浮点比较；保持输出短、输入机制明确。先做动作合法性和语义合成测试，不只测格式。

内部归因检查：在相同候选和探测预算下，LLM 是否比固定动作顺序更早找到有效信息/更好候选？固定策略诊断不新增正式比较臂。

若模型总是提出同一动作，或确定性策略获得同样收益，应归因于统计/探测，而不是 LLM。出现不同动作本身不算增量。

**期望收获：**把 LLM 的价值限定到可验证的“提出什么值得检查”，减少不稳定算术决策和冗长提示成本。

## 9. 调度与 E2E 账本

### 9.1 近期调度选择

初期最多一个数据库执行任务，避免 CBO、多个候选和探测同时争用 HBase。

- 可先启动 CBO 并并行运行 LLM；候选准备/探测会占资源时显式限额。
- 若后续改选，不仅比较候选完整时间，还要考虑 CBO 已完成进度、候选从头执行与切换成本。
- 无可靠剩余时间估计或可恢复状态时，不承诺“随时切换”。可先采用开始执行前的短决策窗口，随后锁定计划。

哪个方案更好由开发时间线决定，不能在文档中假定都有无损切换能力。

### 9.2 选择与评估分开

决策时比较未来剩余成本；最终成绩始终包含已经花掉的模型、探测和废弃执行成本。沉没成本可不影响下一步最优选择，但不能从 E2E 删除。

真实 E2E 用单调时钟记录请求开始到答案可返回。规划、执行、探测有重叠时，不把完整区间简单相加。

逐条等待 LLM 的短查询仍有延迟下界。若改为先返回 CBO、后台继续学习，必须另报协议，不能用于宣称当前查询由 LLM 获胜。

## 10. 中期扩展：查询内分区混合访问计划

### 10.1 研究假设

现有选择大多是整条查询统一采用 P_T/P_Z/P_TZ。若不同时段或区域的相关性、密度和碎片化差别很大，可能不存在一个处处最好的访问路径。

可研究将查询分成少量可验证区域，各区域使用不同访问路径，然后合并候选并进行原有精确处理。LLM 提议有限的分区模板，反馈统计判断是否有收益。

### 10.2 必须先证明的条件

- 分区覆盖原查询全部语义区域，无遗漏；边界半开规则一致。
- 轨迹/chunk 跨分区时正确合并和去重。
- 仍进行原有精确过滤和必要的完整轨迹重建。
- 相似度与 Top-K 最终按全局语义计算，不能直接拼接局部 Top-K。
- 分区数量有界，额外扫描、合并、验证和规划成本全部计入。

第一版可限制两分区、有限模板，避免任意表达式搜索。但先检查当前 IR、编译器和验证器是否能表达此类计划，不假设已有支持。

### 10.3 推进条件

只有局部探测确实观察到区域间访问路径优劣反转，并且潜在节省大于分区成本，才进入实现。若全区域同一计划最好，不为创新而强加分区。

**期望收获：**扩展真正的候选机会空间。是否优于 CBO、是否具备研究新颖性都需独立验证，不能从概念直接得出结论。

## 11. 可选的长期方向：摊薄模型成本

若未来允许放宽每条在线调用，可让 LLM 离线提出参数化改写规则，在线快速匹配、验证和应用。规则绑定语义条件、统计适用范围、快照/布局及规则版本，不能是 query ID→答案缓存。

这有可能摊薄推理成本，但属于不同方法定位。当前不默认采用，不混入逐条 LLM-on 结果。无论何种模式，规则效果必须在未知查询上验证。

## 12. 最小开发顺序与代码检查入口

### 步骤 1：证据链与特征口径

检查 `CboLlmProposalArm` 的原始输出、门控与投机字段，`SuiteRunner` 和汇总脚本的 schema；核对 `BenefitCalibrator`、`FastCost`、`CostFeaturesExtractor` 的训练/在线特征口径。

交付先是可靠数据，不急于再调门槛。

### 步骤 2：一个探测动作

在当前执行器/统计接口中找到可限额访问入口。只实现联合候选规模探测，带固定种子、资源预算和取消记录。不新增无限制查询执行接口。

### 步骤 3：短动作协议

让 LLM 提议探测或有限候选，程序负责风险算术。非法、无效和无收益动作按固定规则回退。

### 步骤 4：两条机会加普通对照

先使用 AIS DTW、Fréchet 与普通对照检查流程，全部保留开发身份。固定重复和顺序轮换，只有结果可解释才回到九条完整开发配对。

### 步骤 5：冻结后验证

冻结模型、提示、预算、校准和规则，再开展未按 hybrid 胜负筛选的查询验证。任何继续用于调参的集合转为开发集。

## 13. 必要测试与验收

- 原始提议、门控与最终选择互不覆盖，摘要与 JSON 行一致。
- 缺失特征、负/异常预测、单位错误正确处理。
- 训练与在线同口径，当前执行后统计不泄漏到当前决策。
- 探测固定种子可复现，热点/空样本/预算耗尽有明确处理。
- 超时或取消后记录实际后台完成，避免污染下一轮。
- LLM 动作合法性、顺序等价性、无提议、非法输出和回退。
- 新候选完整安全验证，Oracle 回归保持通过。
- 探测暖缓存、并发、废弃工作和资源增加均纳入归因。

成功分层：统计误差降低、机会识别改善、开发净收益、未知查询泛化。不能用前一层代替后一层。

## 14. 建议交付物与停止条件

建议后续保存至 `docs/refine_6/`，本次未创建这些产物：

1. `decision_trace_audit.md`：字段修正及旧摘要差异解释。
2. `feature_contract.md`、`feedback_calibration.md`：在线特征、实际标签、分组与单侧误差验证。
3. `probe_design.md`、`probe_results.jsonl`：抽样、预算、误差改善、超限与成本。
4. `llm_action_eval.md`：动作正确性、信息收益、顺序敏感性与归因。
5. `paired_e2e.jsonl`、`summary.md`：完整正负结果和调用/探测/执行账本。
6. `identity.txt`、`RUN_CONFIG.md`：源码与构建、模型、快照、资源及比较协议。

出现以下情况应停止扩大：

- 探测成本高于改善收益，或样本偏差无法控制。
- 校准在分组验证中不可靠，当前不确定性无法量化。
- LLM 与固定动作策略没有额外价值。
- 调度导致竞争或大量重复执行，净收益消失。
- 候选确实更快，但模型成本始终覆盖不了。

这些都是有效研究结果，不通过硬编码赢家或删除短查询修饰。

## 15. 本轮应获得的最重要结论

1. 当前失败主要是模型选错、估计错误还是门控/调度损失？
2. 在线估计的哪个环节最需要执行反馈？
3. 少量当前查询证据能否以更低成本替代大额保守惩罚？
4. LLM 是否提出了固定策略不易找到的有效检查或候选？
5. 所有成本计入后，是否仍有可重复 E2E 净收益？
6. 是否有证据支持进一步研究分区混合访问，而不只是继续重排已有三个计划？

本轮最有价值的交付应是一个可解释、可控成本的决策闭环，而不是又一版更长提示或更低阈值。只有证据支持，才扩大实验和研究范围。
